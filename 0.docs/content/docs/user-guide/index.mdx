Cette partie est écrite pour le développeur qui arrive, pas pour l'exploitant. Elle explique comment travailler avec les règles du cluster **avant** de les découvrir parce qu'un workspace refuse de démarrer. La partie plateforme (comment l'environnement est construit) reste dans [Development Environment](/docs/dev-env).

Les pages arrivent au fil du plan de durcissement : chacune s'écrit dans la même PR que le changement qu'elle explique.

## Pages

- [Organiser son environnement de dev](/docs/user-guide/organiser-son-env) : projet chapeau ou devfile dans le projet, et les pièges.
- [Le contrat de plateforme](/docs/user-guide/contrat-plateforme) : `weebo.io/platform-contract`, les avertissements, épingler son parent, et ce qui change à chaque contrat.
- [Réseau et accès aux endpoints](/docs/user-guide/reseau-et-acces) : profils réseau, clés d'accès, et les clés réservées à l'admin.
- [Demander un outil de team](/docs/user-guide/outils-de-team) : BuildKit et les outils privilégiés, à la demande.
- [Identité du workspace](/docs/user-guide/identite-workspace) : UID 1234 sans groupe 0, et ce que ça change pour les images et les overrides.

À venir, avec leur phase : démarrer son premier workspace ; le parent commun et le générateur de devfile ; les sidecars du catalogue et écrire son propre composant ; ce qui est bloqué et pourquoi ; dépannage.
