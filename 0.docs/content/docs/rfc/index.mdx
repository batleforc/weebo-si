title: RFC
description: "Propositions de conception pour weebo-si, avant de les construire"
---

Une RFC décrit une brique avant qu'on la construise : ce qu'elle résout, son contrat, sa sécurité, son exploitation et les alternatives écartées. Elle suit le gabarit de [weebo-si-hardening](https://github.com/batleforc/weebo-si-hardening/blob/main/docs/rfc/0000-template.md).

Statuts : `Draft` (en discussion), `Accepted` (décidée, questions bloquantes tranchées), `Implemented` (en place et vérifiée), `Superseded`.

## Liste

| # | Titre | Statut |
| --- | --- | --- |
| [0001](/docs/rfc/0001-stalwart) | Stalwart, messagerie interne, et l'opérateur weebo-stalwart | Draft |
| [0002](/docs/rfc/0002-liaison) | La brique de liaison : en-têtes `link.weebo.io`, weebo-link et hooks d'admission | Draft |
| [0003](/docs/rfc/0003-authentik-ecritures) | weebo-authentik n'écrit que ce qui diffère | Draft |
| [0005](/docs/rfc/0005-proxyauthk8s-agent-weebo-si) | ProxyAuthK8S sur Weebo5, un agent dans Weebo-SI | Draft |
